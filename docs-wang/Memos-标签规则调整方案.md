# Memos 标签规则调整方案

## 背景

flomo 导入后，部分原始标签会被 Memos 当前标签解析规则截断，例如：

- `#Books/笔记的方法/2.记录篇/2.标签分类` 会被识别为 `Books/笔记的方法/2`
- `#Books/九宫格写作法/01用“九宫格×自问自答”变身写作达人` 会被识别为 `Books/九宫格写作法/01用`

这不是 flomo 导入解析丢内容，而是 Memos 当前标签语法偏保守：`.`、中文引号、`×` 等符号不是合法标签字符，标签扫描会在这些字符前停止。

## 当前规则位置

后端标签提取：

- `internal/markdown/parser/tag.go`
- `internal/markdown/extensions/tag.go`
- `internal/markdown/markdown.go`

前端标签识别与渲染：

- `web/src/utils/tag-grammar.ts`
- `web/src/utils/remark-plugins/remark-tag.ts`

相关测试：

- `internal/markdown/parser/tag_test.go`
- `internal/markdown/markdown_test.go`
- 前端 tag grammar / memo content 相关测试

AI 工具标签校验：

- `internal/ai/tools/memo_helpers.go`

## 目标

1. 兼容 flomo 风格的长标签，尽量保留用户原有标签信息。
2. 前后端标签识别结果一致。
3. AI 工具的添加、删除、重命名标签能力同步支持新规则。
4. 后续提供标签重命名/清理能力，让用户能把导入后的长标签整理成自己喜欢的格式。

## MVP 范围

当前 MVP 建议只做两件事：

1. 支持更接近 flomo 的宽松标签规则。
2. 支持标签重命名。

不在 MVP 中展开复杂标签管理能力，例如批量合并、批量删除、导入后自动清理规则、标签别名等。这些可以在标签重命名稳定后再做。

## MVP 入口设计

入口放在当前侧边栏标签行的“置顶”图标位置：

- 将单一置顶图标改为“更多/选项”图标。
- 点击后打开下拉菜单。
- 菜单包含：
  - 置顶 / 取消置顶
  - 编辑名称

这样做的好处：

- 用户看到某个标签时，可以就地处理它。
- 不需要先进入设置页再找标签。
- 兼容当前平铺标签列表和树形标签列表。
- 后续如果要增加“隐藏内容”“设置颜色”“删除规则”等，也可以自然放进同一个菜单。

实现上需要同时改：

- `web/src/components/AppSidebar/TagsSection.tsx`
- `web/src/components/TagTree.tsx`

当前两个组件都在标签行尾部渲染置顶按钮。MVP 可以抽出一个小的 `TagActionMenu`，减少平铺和树形模式重复逻辑。

## 置顶标签展示规则

当前实现会把已置顶标签从普通 `TAGS` 区域中过滤掉，只保留在“置顶标签”区域。这会导致树形标签出现一个问题：

- 例如存在 `#life/1/2/3/4/5`
- 当 `life` 被置顶后，`life` 会从普通树数据里移除
- 子标签仍在普通树中，于是 `life` 会被重新构造成一个没有 `amount` 的结构节点
- 结构节点点击行为是展开/收起，导致用户不能在普通树里点击选择 `#life`

MVP 调整：

- 置顶标签继续显示在“置顶标签”区域，作为快捷入口。
- 普通 `TAGS` 区域不再隐藏已置顶标签。
- 平铺模式和树形模式都展示完整标签集合。
- 标签是否置顶只影响行尾菜单状态或图标高亮，不影响它是否出现在完整标签列表中。

这样可以保证：

- `#life` 置顶后，仍然能在树形原位置点击选择。
- 展开/收起只由箭头控制。
- “置顶标签”区和 `TAGS` 区可以重复显示同一个标签，但语义不同：前者是快捷入口，后者是完整目录。

## 标签重命名行为

“编辑名称”建议弹出一个轻量对话框：

- 标题：编辑标签名称
- 当前标签：只读显示原标签
- 新名称：输入框，默认填入当前标签名
- 确认后批量更新当前用户有权限修改的 memo 内容

底层逻辑：

1. 查找当前用户包含旧标签的 memo。
2. 对每条 memo 调用现有 markdown `RenameTag` 逻辑替换标签源码。
3. 通过现有 memo 更新流程保存内容，并重建 payload。
4. 同步迁移用户标签设置里的 metadata，例如置顶、颜色、隐藏内容：
   - 如果旧标签有 metadata，新标签没有，则移动 metadata。
   - 如果新标签已有 metadata，需要保守合并，至少保留新标签现有设置。

需要注意：

- 只重命名“直接标签”，例如从 `Books/旧` 改到 `Books/新`。
- 因为 payload 会展开层级标签，筛选 `Books` 会命中很多子标签；重命名时必须只替换 markdown 中精确匹配的旧标签源码。
- 如果标签出现在代码块、链接文本、链接 URL 中，仍应沿用现有 `RenameTag` 的跳过规则。

## 推荐方案

推荐采用“更接近 flomo 的宽松标签规则”：

- `#` 后开始标签。
- 空白、换行、另一个 `#` 作为明确边界。
- `/` 继续作为层级分隔符。
- 允许常见标题符号进入标签，例如：
  - `.`
  - `·`
  - `_`
  - `:`
  - `：`
  - `-`
  - `+`
  - `&`
  - `×`
  - `“”`
  - `‘’`
  - `（）`
  - `()`
  - `《》`
  - `、`
- 继续拒绝空标签、纯 `/`、连续 `/`、首尾 `/` 等明显异常层级。

这个方案会让 `#todo.` 被识别为标签 `todo.`。这是一个行为变化，但可接受，因为：

- flomo 迁移时，完整保留标签比自动截断更重要。
- 用户后续可以通过标签重命名或手动编辑清理。
- 当前 Memos 已经支持底层 `RenameTag`，后续可以补 UI 或 AI 批量整理能力。

## 备选方案

更保守的方案是只允许“中间标点”：

- `2.记录篇` 中的 `.` 合法。
- `#todo.` 末尾的 `.` 不计入标签。

优点是更贴近传统 Markdown 书写习惯；缺点是规则复杂，中文标题标签中很多符号是否算“中间”会产生边界争议，也不如 flomo 兼容彻底。

当前更建议先采用宽松方案。

## 实现要点

后端：

1. 调整 `internal/markdown/parser/tag.go` 中的 segment starter / continuation 判断。
2. 保持 `/` 层级逻辑，但扩展 segment 内可接受字符。
3. 保证 `ExtractTags` 的层级展开仍然正确，例如 `book/a.b/c` 展开为：
   - `book`
   - `book/a.b`
   - `book/a.b/c`
4. 更新 `internal/ai/tools/memo_helpers.go` 的 `validateTag`。当前会用 `ExtractTags("#"+tag)` 校验，只要 parser 支持，新标签多数会自然通过；但仍需确认空白、`#`、异常 `/` 被拒绝。

前端：

1. 调整 `web/src/utils/tag-grammar.ts` 的 `isExtensionUnit` 或新增 `isTagPunctuation`。
2. 与后端保持同一批可接受字符。
3. 确认 memo 渲染、标签点击、标签输入提示都按同样边界工作。

测试：

1. 后端 parser 测试新增：
   - `#Books/笔记的方法/2.记录篇/2.标签分类`
   - `#Books/九宫格写作法/01用“九宫格×自问自答”变身写作达人`
   - `#todo.`
   - `#a:b`
   - `#中文（括号）`
   - `#book//bad` 仍只识别到 `book`
2. 后端 `ExtractTags` 测试新增层级展开断言。
3. 前端 tag grammar 增加同等 case。
4. AI 工具测试补充 add / rename 新规则标签。

## 风险与影响

- `#todo.`、`#done,` 这类句尾写法可能会把标点计入标签。
- 标签数量可能因为历史文本中的句尾标点变多。
- 如果用户已经依赖旧规则，部分标签统计会变化。
- 前后端规则必须一起改，否则会出现“后端识别了，前端没高亮”或反过来的不一致。

## 后续配套功能

建议单独做一个“标签整理”能力：

1. 标签列表支持重命名标签。
2. 支持批量把一个标签替换为另一个标签。
3. 支持 AI 工具按规则批量整理导入后的 flomo 标签。
4. 支持预览：显示会影响多少条 memo，再执行替换。

## 建议拆分

第一步：调整标签 parser 和测试，保证 flomo 标签完整识别。

第二步：增强 AI 工具，确认复杂标签能添加、删除、重命名。

第三步：做标签管理页的批量重命名 UI。
